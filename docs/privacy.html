Privacy Policy

Last updated: October 16, 2026

Muesli is local-first. Speech-to-text runs on your Mac by default, and recordings stay on your Mac. Text leaves your Mac only for features that use an AI provider you set up (meeting summaries, folder suggestions, transcript cleanup, Quill, Ask Meetings, computer use) or for iCloud sync when you turn it on. Audio leaves your Mac only when you choose a hosted dictation provider. Muesli has no account system and no server that receives your recordings, transcripts, or notes.

What Muesli Does

Muesli is a macOS application for dictation and meeting transcription. It converts speech to text with on-device models (CoreML, the Apple Neural Engine, and MLX). Hosted dictation through OpenAI or OpenRouter is available only when you select and configure it.

Data That Stays on Your Device

  • Audio recordings — microphone and system audio captured during dictation and meetings. Dictation audio is sent out only while you have OpenAI or OpenRouter selected as the dictation provider (see below).
  • Transcripts, meeting notes, and dictation history — stored in a local SQLite database.
  • Configuration — stored in a local JSON file. API keys you enter are stored on your Mac.
  • Calendar events — read from the macOS Calendar database (EventKit). Muesli does not connect to a calendar service itself; accounts such as Google or Exchange reach it through macOS Internet Accounts.
  • Call participant names — when "Read participant names from calls" is on (the default), Muesli reads the participant list of a supported browser call page through the macOS Accessibility API, on your Mac.
  • Screen context — when you turn on app context, Muesli reads the frontmost app's name and the text around the cursor through the Accessibility API, and can optionally run on-device OCR of the screen.

Network Activity With No User Content

These requests carry none of your recordings, transcripts, or notes:

  • Model downloads — speech, speaker, and cleanup models are downloaded from assets.muesli.works (a checksum-pinned mirror for some Parakeet and Whisper models) and from huggingface.co and its CDN. The model you pick downloads during onboarding; speaker models download on launch for meeting users if they are missing. When Nemotron is installed, opening the Models tab checks Hugging Face for a newer version.
  • Update checks — builds that have an update feed check it automatically with Sparkle (the feed set at build time; the default is muesli-hq.github.io). The request carries the app version, not a system profile.
  • Push registration — builds signed for iCloud register with Apple Push Notification service on every launch, even when sync is off.
  • Claude Code status — if the claude command-line tool is installed, showing the Claude Code option runs claude auth status. Muesli sends nothing to it; the tool may contact Anthropic on its own.

AI Providers You Choose

Meeting summaries, meeting titles, folder suggestions, and Ask Meetings use the meeting summary backend. The choices are:

  • ChatGPT (the default) — sign in with your ChatGPT account. Sign-in and token refresh go to auth.openai.com; requests go to chatgpt.com. Nothing is sent until you sign in.
  • OpenAI — your API key; requests go to api.openai.com.
  • Anthropic — your API key; requests go to api.anthropic.com.
  • Claude Code — Muesli runs your installed claude tool and passes it the transcript; that tool decides where it sends it.
  • OpenRouter — your account or key; requests go to openrouter.ai and on to the model provider you pick.
  • Ollama and LM Studio — a server you run, localhost by default.
  • Custom LLM — any OpenAI- or Anthropic-format endpoint you enter.

What each feature sends to that backend:

  • Meeting summaries and titles — the transcript, meeting title, your notes, participant names (from the call page and calendar attendees), and screen context if app context is on.
  • Folder suggestions — on by default ("Suggest folders for meetings"). After a meeting that no folder rule matches, the meeting title, participant names, the start of your notes, and your folder names are sent to the backend.
  • Ask Meetings — your question and the passages of transcripts and notes it retrieves, when you send a message.

Meetings you mark private are kept out of summaries, titles, folder suggestions, and Ask Meetings unless you allow that backend for private meetings in Settings.

Other features with their own provider setting, all off by default:

  • Hosted dictation — with OpenAI selected, microphone audio streams to OpenAI's Realtime transcription API; with OpenRouter selected, the finished recording is uploaded to the transcription model you pick.
  • AI transcript cleanup and Quill — use on-device models by default. With a hosted backend selected, the dictated or selected text (and app context, if on) is sent to it.
  • Computer use — when you turn on its shortcut, your spoken command, a screenshot of the frontmost window, and that window's accessibility text go to the planner model (ChatGPT unless you choose a local planner). The planner can also ask for the text of the current browser page and the titles of open browser tabs, which are then sent to it.

Each provider's own privacy policy governs what it does with the data.

iCloud Sync

Off by default. When you turn it on, dictation text and meeting titles, transcripts, summaries, and notes sync through your private iCloud account (CloudKit) to your other devices. Audio is not synced.

macOS Permissions

  • Microphone — to capture your voice for dictation and meetings.
  • System Audio — to capture the other side of a meeting through a Core Audio process tap (the default).
  • Screen Recording — for the ScreenCaptureKit system-audio fallback, for meeting screen context (accessibility text plus on-device OCR screenshots) when app context is on, and for computer-use screenshots.
  • Accessibility — to paste text, read app context, and read call participant names.
  • Input Monitoring — to detect the dictation shortcut.
  • Calendar — to read upcoming events from the macOS Calendar database.
  • Contacts — when you pick meeting participants from Contacts or save one as a new contact. This happens on your Mac.

Anonymous Usage Analytics

Muesli can send usage signals to TelemetryDeck, only if you turn on "Share anonymous usage analytics" in Settings > General > Privacy. It is off by default, and builds made without an analytics ID record no usage signals. When on, signals record feature use (for example, that a dictation or meeting completed and which backend ran) and, after a hard failure, an allowlisted diagnostic category, workflow stage, transcription backend and model, and a random incident ID. They never include audio, transcripts, notes, titles, keys, or file paths. The TelemetryDeck SDK (version 2.11.0) adds its default metadata to each signal: a hashed random install ID and a session ID; the app version and build and the SDK version; the macOS version, device model, architecture, screen resolution and scale; language, locale, region, time zone, layout direction, and color scheme; the calendar day, week, month, and hour the signal was sent; the macOS Reduce Motion and Invert Colors settings; build-environment flags (debug, App Store, TestFlight, simulator); and usage history (first session date, number and length of sessions, days used). It also sends its own session-started and new-install signals. While analytics are off, Muesli does not start the TelemetryDeck SDK at all, so it neither records nor sends anything. If you turn analytics off while Muesli is running, the SDK stops recording new signals right away; signals recorded before that may still be sent, and any still unsent when Muesli quits stay in TelemetryDeck's local queue on your Mac, which Muesli sends only if you turn analytics back on (other apps that use TelemetryDeck share that queue and may send it). See TelemetryDeck's privacy page for how it handles that data.

Open Source

Muesli's source code is publicly available on GitHub under the MIT license, so every statement here can be checked against the code.

Children's Privacy

Muesli is not directed at children under 13. We do not knowingly collect data from children.

Changes to This Policy

If this policy changes, the updated version will be posted here with a revised date. Muesli has no way to notify you of changes because it does not collect contact information.
